# 建玉の計画（Phase 2）

Entry / SL / TP / Lot / 必要証拠金を出す層。**発注はしない。**

## 最初に読むこと

Phase 1 の検証で、こう出ています（実データ26銘柄・約2か月半）。

| 組 | 勝率 | 平均R |
|---|---:|---:|
| 建てたもの | 31.6% | −0.117 |
| コイン投げ | 31.3% | −0.115 |

**判断とコイン投げに差がありません。** つまりこの層が出す数字は
「その方向に賭けるなら、この幅・この枚数」という**算術**であって、
儲かる根拠ではありません。計画の中に必ずこの注記を入れてあり、
数字だけ抜き出して読めないようにしています。

## 出すもの・出さないもの

### 出すもの

| 項目 | 中身 |
|---|---|
| 建値 | **帯**（1点ではない）。ATR の ±0.15倍 |
| 損切り | 直近の転換点の外側、または ATR の2.0倍。**どちらを採ったか明示** |
| 利確 | TP1/TP2/TP3 を 1.5R / 2.5R / 3.5R。帯に当たるなら手前で止める |
| 数量 | 許容損失から逆算。**整数**に切り捨て |
| 必要証拠金 | 推定。基軸通貨の量 × 円レート × 4% |
| 損切り時の額 | 当たったら失う金額 |
| スプレッド費用 | 建てた時点で先に払う額 |

### 出さないもの

- **勝率を掛けた期待値。** 優位性が測れていないので、名乗れば嘘になる
- **「信頼度○○%」。** 点数は勝率ではない
- **保有時間の目安。** 検証していない
- **ロスカット水準の判定。** 業者の計算が正で、こちらでは出さない

## 枚数の出し方（順序が大事）

```
① いくらまで失ってよいか（資金 × リスク%）
② 損切り幅（pips）
③ 1Lot・1pip あたりの金額（円換算後）
④ Lot = ① ÷ (② × ③)  → 刻みに切り捨て
```

**「何Lot買えるか」から始めない。** そこから始めると損失額が後追いになる。

### pip の価値は決済通貨で出る

ここを取り違えると、損失額が桁違いになる。

| 銘柄 | 決済通貨 | 1Lot1pip | 円換算 |
|---|---|---|---|
| USDJPY | JPY | 100円 | 換算不要 |
| EURUSD | USD | 1 USD | × USDJPY |
| EURGBP | GBP | 1 GBP | × GBPJPY |
| GBPNZD | NZD | 1 NZD | × NZDJPY |

**換算レートが無ければ計算しない。** 1.0 で代用すれば、EURGBP の損失が
1/200 に見える。無いときは計画を出さず、理由を返す。

### 証拠金は基軸通貨の量で決まる

EURUSD を 2.1Lot なら 21,000 **EUR**。円では EURJPY × 21,000 × 4%。
決済通貨ではなく基軸通貨であることに注意。

## 取引単位（一次情報で確認済み）

外為オンライン「取引要綱詳細」（2026-09-14 取得）より。

| コース | 単位 | 上限 | ZARJPY・MXNJPY |
|---|---|---|---|
| L25R／L25 1万通貨 | 1万通貨（数量1） | 数量100 | **10万通貨（数量1）** |
| L25R／L25 1,000通貨 | 1,000通貨（数量1） | 数量300 | **1万通貨（数量1）** |

**ZARJPY と MXNJPY だけ単位が10倍。** 揃えて扱うと、その2銘柄だけ建玉が
10倍になり、決めたリスクが10倍ずれる。実際そうなっていたので直した。

**発注は「数量」（整数）で行う。** 0.1Lot のような刻みは1万通貨コースには
存在しない。損益とスワップの計算には「1万通貨」を単位として使う
（業者のスワップ表もその単位で公表されている）が、**発注の単位とは別物**。

## レバレッジと証拠金（一次情報で確認済み）

> 個人のお客様の取引に必要な証拠金は、各通貨のレートにより決定され、
> お取引額の4％相当となります。証拠金の25倍までのお取引が可能です。
> — 外為オンライン 取引要綱詳細（2026-09-14 取得）

ただし同じページに「**取引証拠金の金額は、取引営業日毎に変わり、数量1
あたりの値を表示しております**」とある。つまり実際の証拠金は業者が
日々公表する値であって、当日レートからの4%計算は**推定**にすぎない。
発注前に取引画面の値を確認すること。

## 切り捨てる理由

数量は整数に**切り捨てる**。切り上げると、決めたリスクを超える。
1%と決めたのに1.05%失うのは、リスク管理をしていないのと同じ。

## 建てない条件

| 条件 | なぜ |
|---|---|
| 分析が BUY/SELL でない | 見送りに「もし買うなら」を添えない |
| 有効期限が切れている | 根拠が失われている |
| 換算レートが無い | いくら損するか分からない |
| 許容損失で最小Lotに届かない | 損切り幅が資金に対して広すぎる |
| 必要証拠金が資金の20%超 | 一度の取引に資金を寄せすぎ |
| リスク割合が上限（2%）超 | 指定そのものを受け付けない |
| TP1 が 1.5R に届かない | 帯が近く、抜ける前提の数字になる |

## 設定で一度失敗したこと

`r_multiples` の先頭を 1.0 にしたまま `min_rr` を 1.5 にしていた。
TP1 は最大1.0Rなので**条件を構造的に満たせず、計画が永久に作れない**
状態になった。先頭は必ず `min_rr` 以上にする（試験で固定してある）。

また、`_UNVERIFIED` という鍵名で業者仕様の未確認注記を書いていたが、
設定読み込みが `_` で始まる鍵を落とすため、**注記が API に届いていなかった**。
`unverified_note` に改名した。**隠してはいけない情報を、注記の書式で
隠してしまう**のは起こりやすい失敗。

## スワップ

**データを持っていない。** `swap_state` は `UNKNOWN` を返し、画面にも
「不明」と出す。0円と書けば費用ゼロに見えるし、適当な数字を入れれば嘘になる。
業者の表を取り込むときは、出所と取得日を `config/account.json` に残すこと。

## スワップ表の取り込み

**数字はこちらで作らない。** 業者の表を写したものだけを入れる。

```bash
# 1. 雛形をコピーして、業者の表から値を写す
cp data/swap_template.csv mine.csv

# 2. 取り込む（--source と --as-of は必須）
python scripts/import_swap.py --csv mine.csv     --source "外為オンライン 店頭FX スワップポイント" --as-of 2026-09-12

# 3. 中身だけ確かめるなら
python scripts/import_swap.py --csv mine.csv --source "..." --as-of ... --dry-run
```

CSV の形:

```
symbol,buy,sell
USDJPY,251,-311
EURJPY,-95,55
```

- `buy` は買い持ち、`sell` は売り持ちを**1日**持ち越したときの円（1Lot = 1万通貨）
- 空欄の行は飛ばす。分かる銘柄だけ入れればよい
- 表に無い銘柄は計画で「不明」のまま。**0円にはしない**

### 外為オンラインの表は自動で取り込める

同社は月次の「スワップポイント一覧表」を PDF で公開している。

```bash
python scripts/fetch_swap_gaitame.py --out swap.csv
python scripts/import_swap.py --csv swap.csv     --source "外為オンライン スワップポイント一覧表 2026年9月（PDF）" --as-of 2026-09-11
```

`robots.txt` は PDF の取得を禁じていないことを確認済み。
ブラウザのふりをする User-Agent は使っていない。

**表の読み方で2回つまずいたので、その両方を試験にしてある。**

1. **値は「付与日数ぶんの合計」。** 水曜は3日分、連休前は4日分がまとめて
   付く。そのまま1日あたりとして読むと3〜4倍になる。付与日数で割る。
   （検算: USD/CAD 09/10 は3日分 −210/75 → 1日 −70/25。翌日の1日分の
   値 −70/25 と一致する）
2. **付与日数は銘柄ごとに違う。** 同じ 2026/09/11 でも USD/CAD は1日、
   MXN/JPY は2日だった。最初「付与日数が1の日だけ拾う」実装にしたため、
   **MXN/JPY を丸ごと落とした**（25/26銘柄しか取れなかった）。

まだ決まっていない日は `-` で並んでいる。**0として読まない。**
付与日数0の日は「その日は付かない」という意味なので、1日あたりの
レートの手がかりにはならず、飛ばす。

単位は PDF の注記（「スワップポイントは1万通貨あたりの値です」）を
毎回確かめてから取り込む。注記が見当たらなければ、単位が変わった
可能性があるので取り込みを中止する。

### 出所と日付が必須な理由

スワップは毎日変わる。日付の無い数字は、それが今の値かどうか後から
確かめられない。だから `--source` と `--as-of` は必須にしてあり、
`stale_after_days`（既定7日）を過ぎた表は `STALE` として警告する。

### 向きで額も符号も変わる

買い持ちと売り持ちで額が違い、片方が受取・片方が支払いになるのが普通。
**取り違えると、受け取るはずが払うことになる。** そのため
`swap_estimate()` は向きを必ず受け取り、`buy` / `sell` を選び分ける。

### 取り込みで弾くもの

**壊れた行を黙って直さない。** 飛ばして理由を返す。

| 弾く条件 | 理由 |
|---|---|
| 設定に無い銘柄 | 打ち間違いの可能性 |
| 数値でない | 写し損ね |
| 片側だけ空 | 向きを判定できない |
| 絶対値が1万円超 | 1Lot1日としては桁がおかしい |
| 銘柄の重複 | どちらが正か決められない |

加えて、買いも売りも受取になっている行は「写し間違いの可能性」として
**警告するが直さない**。勝手に符号を反転させるほうが危ない。

### 3日分のロールオーバー

水曜（一部は木曜）をまたぐと3日分付くことがある。このアプリは
**1日あたりの額しか出さず、何日分になるかは判定しない**。保有期間を
予測していないため。

## 業者仕様について

レバレッジ25倍・証拠金4%は、利用者から共有された文章の記載で、
**一次情報を確認していない**。`config/account.json` の `unverified_note` に
その旨を書き、API と画面にも出している。証拠金は実際の取引画面の値が正。

## 発注しない

注文の口は作っていない（試験で `order` / `execute` を含む経路が
存在しないことを確認している）。数字を出すところまでで、発注は利用者が
業者の画面で行う。
