# 試験

## 走らせ方

プロジェクト直下で。

```bash
.venv/Scripts/python.exe -m pytest tests -q      # Windows
.venv/bin/python -m pytest tests -q              # macOS / Linux
```

`tests/conftest.py` が `backend/` を `sys.path` に入れるので、
インストールや `PYTHONPATH` の設定は要らない。

## 何を確かめているか

### 指標

**既知の答えと突き合わせる。** 自分の実装の出力を自分で正解にしない。

- SMA / EMA は手で計算できる短い系列で確認
- RSI・ATR・ADX は **Wilder 平滑**であることを確認（単純平均ではない）
- 足りない期間は `None` を返し、0 で埋めない
- ボリンジャーは中心・上・下・幅を返す

`relative_level()`（中央値に対する比）にも試験がある。以前ここに
分位を使っていて、**ほぼ一定の系列で 0 か 1 に張り付き、全銘柄が
「変動が異常」で見送りになった**。分位は定義上どんな系列でも一様に散るので、
「普段と比べて極端か」の判定には使えない。

### 市場データ

- 足1本の整合（`high < low` などを弾く）
- 系列の昇順・重複なし
- CSV の壊れた行を飛ばし、飛ばしたことを記録する
- 置き場の外を読ませない（`../../etc/passwd`）
- 未実装の供給元が `NotImplementedError` を投げる
- 合成データが**プロセスをまたいで同じ**になる
- 相対パスがプロジェクト基点に付く
- `.env` が環境変数を**上書きしない**

### 安全境界

**「機能が動く」ではなく「危ない状態を通さない」ための試験。**
指定された再現ケースをそのまま置いてある。実装を緩めれば必ず落ちる。

| 再現ケース | 期待 |
|---|---|
| `inf` / `NaN` の価格 | 境界で拒否（`inf` は `v > 0` を通るので明示的に弾く） |
| H1 として2時間間隔240本 | `ok=False`、「別の時間足の足が渡されています」 |
| H1上昇・H4下降で score 95 | NO_TRADE と競合理由 |
| H4 の向きが UNKNOWN | NO_TRADE（分からないことを「競合なし」にしない） |
| 気配値80秒前・上限90秒・TTL60秒 | 有効期限は残り10秒 |
| 期限切れの判断を API から取得 | `signal=NO_TRADE` / `direction=NEUTRAL` |
| CSV 取り込みに未知の銘柄・時間足 | HTTP 422 |
| 未実装の供給元を呼ぶ | `NotImplementedError` |

週末の空白を欠落と数えないことも試験してある。数えれば月曜の朝は必ず
「壊れている」と言い出す道具になる。

統合の試験（monkeypatch ではなく、実際の指標→相場つき→シグナルを通す）も
置いてある。BUY/SELL/WAIT/NO_TRADE のどれかに固定されていたら落ちる。

### 検証（未来を見ていないこと）

**ここがいちばん厳しい。** 検証の道具が未来を覗いていたら、出てくる成績は
本物より良く見える。それを信じて建てれば実際に負ける。

- 同じ時刻の判断が、その先の足を持っているか否かで**1ビットも変わらない**
- 打ち切りより後ろの足を返さない
- 建玉は判断した足の**次の**足（終値で建てない）
- 損切りと利確の両方に触れた足は**損切り**に数える
- 銘柄構成の罠で誤らないこと（同じ落とし穴をそのまま試験にしてある）
- 件数が足りない区分で勝率を名乗らないこと
- 同じ条件なら同じ結果になること

未来を見ない試験が**素通りしていないこと**も確かめた。`HistoryProvider` の
打ち切りを故意に壊すと、該当する3件が実際に落ちる。

### エンジン

- HH/HL/LH/LL の判定と BOS/CHOCH
- 相場つきが上昇・下降・持ち合い・放れで正しく変わる
- 強制条件が1つでも当たれば NO_TRADE
- **点数が高くても強制条件を上書きできない**
- 向きが NEUTRAL なら BUY/SELL にならない
- 例外が出ても NO_TRADE に倒れる

### API

- `/health` が繋がる
- 26ペアが返る
- 分析結果の形が `AnalysisResult` に合う
- 並べ替えが順位つきで返る
- 知らないペアは 404
- `POST /api/dev/load-csv` は `FX_ENV` が development のときだけ

## 試験で見つけた不具合

**試験を通すために実装を緩めたことはない。** 通らなかったときは
実装か試験のどちらが間違っているかを決めてから直した。

| 症状 | 原因 | 直し方 |
|---|---|---|
| 全26銘柄が NO_TRADE | `min_candles` の `_comment` を時間足として読んでいた | 読み込み時に `_` で始まる鍵を落とす |
| 同じ入力で毎回違う合成データ | 組み込み `hash()` の無作為化 | `sha256` で種を作る |
| 強い下降トレンドが LOW_VOLATILITY | 変動の判定をトレンドより先に置いていた | トレンド→放れ→変動→持ち合いの順に |
| 全銘柄が「変動が異常」 | 分位を極端さの判定に使っていた | 中央値に対する比に変更 |
| 支持帯が ATR の 5.44 倍も先 | 60本の最安値だけを見ていた | 直近の転換点・EMA50 も候補にし、最も近いものを採る |
| 構造が常に UNKNOWN | 転換点の探索範囲が 120本では足りなかった | 250本に |
| `backend/database/` が別にできる | 相対パスを起動位置に付けていた | プロジェクト基点に付ける |
| `.env` が効かない | 誰も読んでいなかった | 環境を上書きしない読み込みを追加 |
| 検証の前半が丸ごと無効 | M15 と M5 を同じ本数取っていた（M5 は約1/3の期間しか覆えない） | 時間足ごとに必要本数を計算 |
| 「選別すると成績が下がる」 | 比べた相手の銘柄構成が違った | 銘柄を揃える `stratified_compare()` |
| 検証結果が走らせるたびに揺れる | 合成データの終端が「いま」だった | 終端を固定できるようにした |
| ZARJPY・MXNJPY のリスクが10倍ずれる | 取引単位を全銘柄1万通貨としていた（実際は10万通貨） | 取引要綱を確認し銘柄ごとの単位に |
| 存在しない 0.1Lot 刻みで計算 | 1万通貨コースの最小は数量1 | 整数の数量に切り捨て |
| 実データの基準が勝率14%（有り得ない値） | 強制条件で弾いた場面を基準に混ぜていた | `hard_blocked` で分け、基準は通った場面だけに |
| 項目ごとの分析だけ弾いた場面込み | 基準を直したときに直し忘れた | 同じ範囲に揃えた |
| CSV のスプレッドが全銘柄一律1.2pips | 実勢は USDJPY 0.9 / GBPNZD 10.0 と10倍以上ちがう | `config/spreads.json` に実勢値 |

試験そのものが間違っていた例も2つある。

- 転換点の試験データに同値が並んでいて、転換点として数えられなかった。
  試験側を直した（`_zigzag`）。
- `test_csv_missing_file_raises` が**実在するファイル**を指していて、
  「ファイルが無いとき」を試験できていなかった。置いていない `D1` に変更し、
  壊れた行の扱いは別の試験に分けた。

そして、試験ではなく**検証のやり方**そのものを間違えた例が1つ。
合成データの終端を3つ変えて「3条件で確かめた」と言いかけたが、値段の道筋は
種で決まるので3回とも**完全に同じ数字**だった。同じ実験を3回書き写しただけ。
重ならない標本の作り方は [backtesting.md](backtesting.md) に書いた。

## 画面側

```bash
cd frontend && npm test             # 5件（node --test、依存追加なし）
cd frontend && npx tsc --noEmit     # 型
cd frontend && npm audit            # 依存の脆弱性
```

期限の判定は安全に関わるので、純粋な関数として `lib/freshness.ts` に
切り出して試験してある。**読めない日時を「有効」として通さない**ことも
確かめている（通すと根拠不明の BUY が画面に残る）。

`next@15.1.6` に脆弱性（CVE-2025-66478）があったので `16.3.4` に上げてある。
いまは `npm audit` が 0 件。

## まだ無いもの

**実データでの検証をしていない。**

検証の仕組みは動く（[docs/backtesting.md](backtesting.md)）が、走らせたのは
合成データの上だけ。したがって、

- 実際の相場での勝率は不明
- 実際の期待値が正かどうかは不明

ここに書いてある「通った」は、**実装が仕様どおり動く**という意味であって、
**取引して儲かる**という意味ではない。
