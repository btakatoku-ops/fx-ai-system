## 0. このアプリでの位置づけ（読み替え）

Phase 1 の実測で、エンジンの BUY/SELL にはコイン投げとの差が出ていない
（`docs/backtesting.md`、向きをそろえた比較でも SHORT −0.5pt・LONG −7.4pt、
いずれも有意でない）。効いていたのは**除外**（強制条件）だけだった。
そのため画面の中心は「朝のボード」（材料の ▲▼■ と除外の理由）に移っている。

これを踏まえて、Phase 2 の「計画」は次のものとして定義する。

- **向きを決めるのは使う人。** 計画は「その向きで建てるなら、この建値・損切り・
  利確・数量・費用・損益」という**算術**で、儲かる根拠ではない。
- **除外の日には計画を作らない。** ボードの除外（強制条件・対立・警戒帯・値幅の
  使い切り・刻限）を、計画の側でも独立に再評価して止める。
- 分離は指示どおり維持する：
  `TechnicalCandidate → PlanDraft → netRR → 独立 gate 再評価 → 最終判定`。
  ただし最終判定は **BUY/SELL ではなく `PLAN_OK` / `NO_TRADE(reason_code)`**。
  このアプリは売買の合図を出さない（出せる根拠が無い）。

## 2. 入出力契約

### 2.1 入力は「スナップショット」でだけ受け取る

計算関数は I/O をしない。呼び手が次の5つを作って渡す。**どれも観測時刻・
有効期限・出典・設定版を持つ。** 1つでも欠ければ計算に入らない（§4）。

| スナップショット | 中身 | 必須の付帯情報 |
|---|---|---|
| `QuoteSnapshot` | 対象銘柄の bid・ask。**利用者が取引画面（MT4）から手で入れる**（決定3） | `observed_at`（入力した時刻）、`valid_until`、`source`=`manual_mt4`、`price_basis`=`bid_ask`。取り込んだ足の終値は**基準価格に使わない**（構造・ATR の計算にだけ使う） |
| `CandidateSnapshot`（= TechnicalCandidate） | **向き（利用者が選ぶ。決定1）**、損切りの構造根拠（転換点の値と時刻）、ATR、利確に使う観測水準の一覧 | 使った足の最終時刻（**それより後の足を使っていない証拠**）、`config_version` |
| `CostSnapshot` | スプレッド（その時点の実値か、表の値か）、滑りの仮定、スワップの状態 | `source`、`as_of`、**仮定か実測かの区別** |
| `ConversionSnapshot` | 円換算に要るレート（損益用 quote→JPY、証拠金用 base→JPY） | 各レートの `observed_at`・`valid_until`・`source`・`price_basis` |
| `InstrumentSpec` + `AccountSnapshot` | 呼値（price_tick）、数量1の通貨量、最小・刻み・上限、証拠金率、コース、資金、1回のリスク%、証拠金上限% | 出典 URL・**確認日**・**適用コース**。業者の事実と研究上の仮定を別の欄に持つ |

加えて **`BoardSnapshot`**（その時点のボードの除外・注意・刻限）を受け取り、
独立 gate の材料にする（§3 の G 段）。

### 2.2 出力は2段に分ける

| 出力 | 意味 | 画面での扱い |
|---|---|---|
| `PlanDraft` | 計算途中の案。建値・損切り・利確・数量・費用込み損益・netRR。**gate を通る前** | 画面に出さない（試験と記録のため） |
| `PlanDecision` | 最終判定。`PLAN_OK` か `NO_TRADE`。NO_TRADE は `reason_code` と文言を必ず持つ。PLAN_OK でも「儲かる根拠ではない」注記を必ず持つ | 画面に出すのはこちらだけ |

**`PlanDraft` をそのまま画面に出す経路を作らない。** 途中の数字が「推奨」に見える。

## 3. 計算順序と丸め

### 3.1 依存関係

```
A 入力の検証（期限・基準・有限値・出典）
│
B 候補（向き・構造・ATR）……使った足の最終時刻 ≤ 判定時刻
│
C 実効建値 = 向きの不利側（買い: 手入力の ask、売り: 手入力の bid）。**手入力が無ければ止める**（足の終値で代用しない）
│
D 確定損切り = 構造点の外側（余裕込み）。帯域の最小距離を満たさなければ停止
│
E/F 費用込みの距離と利確
│   スプレッドは、建値を ask（買い）／bid（売り）に置いた時点で入っている
│   （MT4 では買いの損切り・利確は bid で、売りは ask で判定される）
│   損失距離 = |実効建値 − 損切り| + 2 × 滑り（建て・決済）
│   利確 m 段目 = 「利益距離 = m × 損失距離」になる値（R を費用込みで測る）
│   利益距離 = |TP − 実効建値| − 2 × 滑り
│   帯（抵抗・支持）を越えるなら帯の手前 0.1 ATR に寄せる。その結果 TP1 が
│   m 倍を割れば NET_RR_BELOW_MIN
│   netRR = 利益距離 ÷ 損失距離
│
G 円換算（quote→JPY）。換算レートは期限内で、ストレス係数を不利側に掛ける
│
H 数量 = floor( 許容損失 ÷ 数量1あたり費用込み損失 , 刻み )。最小未満なら停止。上限で頭打ち（頭打ちは注記）
│
I 証拠金（base→JPY × 証拠金率）。上限超なら停止
│
J 独立 gate 再評価（計算結果を見ずに、入力だけから再判定）
│   ボードの除外・刻限・netRR 下限・スワップ跨ぎ・スナップショット期限
│
K PlanDecision
```

**費用を足すと netRR は必ず下がるか同じ**（F の式の単調性）。試験で固定する（§6 T3）。

> **実装で分かったこと（2026-09-28）**：いまの規則のまま TP1 を「総額で 1.5R」に
> 置き、下限 1.5 を費用込みで判定すると、滑りが少しでもあれば**すべての計画が
> 止まる**（費用込みの比は必ず 1.5 を割る）。そこで R の倍数を費用込みで測り、
> TP1 を「費用込みで 1.5 倍」の位置に置く。費用が大きいほど TP は遠くなり、
> 帯に当たって比が下がれば止まる。規則の数字（1.5/2.5/3.5・下限 1.5）は変えていない。

### 3.2 数値と丸め（Decimal）

| 対象 | 型 | 丸め | 向き |
|---|---|---|---|
| 価格（建値・損切り・利確） | `Decimal` | 呼値 `price_tick` に量子化 | **不利側へ**：建値は買いで切り上げ・売りで切り下げ。損切りは建値から遠ざかる側。利確は、帯で止めた段は建値の側（帯を越えない）、それ以外は外側（丸めで m 倍を割らない）。利益額は丸めた値で計算するので多く見せない |
| 距離（pips） | `Decimal` | 丸めない（計算途中） | — |
| 換算レート | `Decimal` | 丸めない | ストレス係数は損失を大きくする側 |
| 数量 | `int` | `ROUND_FLOOR` で刻みに | 切り上げない |
| 損失額（円） | `Decimal` → 表示は整数円 | `ROUND_CEILING` | 大きく見せる |
| 利益額（円） | 同上 | `ROUND_FLOOR` | 小さく見せる |
| netRR | `Decimal` | 小数2桁 `ROUND_FLOOR` | 下限判定は丸め前の値で |

`float` は入力の境界（CSV・JSON）で `Decimal(str(x))` に直し、計算の中では使わない。
非有限値（NaN・∞）は境界で停止（§4 の `PLAN_INVALID_NUMBER`）。

## 4. 未知・不正・失効のときの停止表

**数字を仮置きして UNKNOWN を消さない。** 下の条件は、どれも `NO_TRADE` で止める。

| 段 | 条件 | reason_code | いまの実装 |
|---|---|---|---|
| A | 分析・候補の有効期限切れ | `PLAN_EXPIRED` | ある（文言のみ） |
| A | 気配値の `observed_at` が古い／`valid_until` 超過 | `QUOTE_STALE` | **無い**（C10・C11） |
| A | 手入力の bid・ask が無い | `QUOTE_MISSING` | **無い**（いまは足の終値） |
| A | bid ≥ ask、または実スプレッドが表の wide の3倍超（入力の打ち間違い・指標時の拡大） | `QUOTE_INVALID` | **無い** |
| A | 手入力の値が、取り込んだ足の終値から ATR の3倍以上離れている（別銘柄の値を入れた疑い） | `QUOTE_MISMATCH` | **無い** |
| A | 非有限・0以下の価格・ATR・資金・リスク% | `PLAN_INVALID_NUMBER` | ある（文言のみ） |
| B | 向きが決まっていない | `DIRECTION_UNSET` | ある |
| B | 候補が判定時刻より後の足を使っている | `FUTURE_BAR_USED` | **無い**（仕組みとしては足の確定で担保） |
| C | （手入力の bid・ask から実スプレッドが出るので、表は照合用。表に無い銘柄は照合できない旨を注記し、止めない） | — | C13 の仮置きは**計画では使わない** |
| D | 損切りが建値の反対側／最小距離未満 | `STOP_INVALID` | ある |
| E | 利確を置ける余地が無い | `TARGET_NO_ROOM` | ある |
| F | netRR が下限未満 | `NET_RR_BELOW_MIN` | **総額 RR でしか見ていない**（C5） |
| G | 円換算レートが無い／期限切れ | `CONVERSION_MISSING` / `CONVERSION_STALE` | 無い方はある。期限切れは**無い**。**円が決済通貨の銘柄（GBPJPY・USDJPY・EURJPY）は、手入力の値だけで損益も証拠金も円換算できる**。それ以外は換算レートも手入力が要り、無ければ止める |
| H | 数量が最小未満 | `QTY_BELOW_MIN` | ある |
| H | 1回のリスク%が上限超 | `RISK_ABOVE_CAP` | ある |
| I | 証拠金が上限超 | `MARGIN_ABOVE_CAP` | ある |
| J | ボードが除外（強制条件・対立・警戒帯・値幅使い切り） | `BOARD_EXCLUDED` | **無い**（計画は分析だけを見る） |
| J | 刻限まで足りない／01:00〜日替わり | `DEADLINE` | 分析経由では止まる。計画としては**無い** |
| J | 刻限が日替わりを跨ぐ（スワップ発生） | `ROLLOVER_CROSS` | 設計上起きない（C15）。試験で固定する |
| J | InstrumentSpec の確認日が古い／コース不一致 | `SPEC_UNVERIFIED` | **無い** |

スワップの `UNKNOWN`/`STALE` は、**日計りで日替わりを跨がないので計画は止めない**
（いまと同じ）。ただし `ROLLOVER_CROSS` が起こりうる設定に変えたら、止める側に移す。

## 5. 実装の単位（案）

既存の `trade_plan.py` は**書き換えない**（記録 `plan_for` と `/api/plan` が使っている）。
新しい計算は横に置き、試験で並べて比べてから切り替える。

| 段 | 中身 | 既存機能への影響 |
|---|---|---|
| **P2-1**（初回） | `backend/app/plan_calc.py`：§3 の純粋関数（Decimal、I/O なし）。入力はスナップショットの dataclass、出力は `PlanDraft`／`PlanDecision`。停止は `reason_code` つき | **無し**（どこからも呼ばない） |
| P2-1 | 検証：合成データと `data/real` の CSV で、手計算の期待値・鏡像・境界を確かめる試験（§6） | 無し |
| P2-2 | スナップショットを作る側：気配値の基準と時刻、換算レートの期限、スプレッドの出典、InstrumentSpec の確認日 | `market_data`・`entry_engine` に**読み取り専用の関数を足すだけ** |
| P2-3 | 既存 `build_plan` と `plan_calc` を同じ入力で並べ、差を記録（数量・netRR・停止理由） | 記録の列が増える（既存の行は変えない） |
| P2-4 | API/画面へつなぐ（ボードから「この向きで計画を見る」） | `/api/plan` の中身が変わる。**別途承認のうえ** |

長い I/O（Yahoo 取り込み・ブリーフ読み取り）は計算の外。計算関数は時間切れを
持たない。API 側の時間切れと、再起動時の画面復旧は P2-4 で決める（§7 U7）。

## 6. 受入試験（P2-1 の完了条件）

| # | 試験 | 合格の条件 |
|---|---|---|
| T1 | **買い・売りの鏡像** | 同じ距離・同じ費用なら、損失額・利益額・数量・netRR が一致し、価格が建値を挟んで対称 |
| T2 | **手計算との一致** | USDJPY・EURUSD（換算あり）・EURGBP（交差換算）・ZARJPY（10倍単位）の4例を、表計算で出した期待値と**1円単位で**一致 |
| T3 | **費用を増やして RR が良くならない** | スプレッド・滑りを増やす方向に動かしたとき、netRR は常に減少または同じ（性質試験で乱数入力も） |
| T4 | **最小数量未満** | 許容損失が数量1ぶんの損失に届かなければ `QTY_BELOW_MIN`。0.9 を 1 に切り上げない |
| T5 | **数量の刻みの境界** | ちょうど刻みの倍数、倍数−ε、倍数+ε で floor が正しい（Decimal なので 1e-9 の補正が要らない） |
| T6 | **換算レートの期限** | 期限ちょうどで `CONVERSION_STALE`。期限前は通る。1.0 で代用しない |
| T7 | **将来の足を使わない** | 判定時刻より後の足を混ぜた入力で `FUTURE_BAR_USED`。混ぜなければ結果は不変 |
| T8 | **95点でも NO_TRADE** | 分析の点数が高くても、ボードが除外なら `BOARD_EXCLUDED`（点数は勝率ではない）。**利用者が向きを選んでも、除外の日は計画を出さない** |
| T9 | **一覧と詳細の整合** | 同じスナップショットから、ランキング行と計画詳細が同じ判定・同じ理由コードを返す |
| T10 | **仮置き禁止** | 手入力の bid・ask が無ければ `QUOTE_MISSING`。足の終値や 3.0pips で計算しない |
| T14 | **手入力の検査** | bid ≥ ask で `QUOTE_INVALID`、wide の3倍超のスプレッドで `QUOTE_INVALID`、終値から ATR×3 以上ずれた値で `QUOTE_MISMATCH`、入力から有効期限を過ぎたら `QUOTE_STALE` |
| T15 | **向きは利用者の選択** | 同じスナップショットで向きだけ変えた2通りが、T1 の鏡像を満たす。エンジンの BUY/SELL・点数は計画に影響しない |
| T11 | **刻限** | 23:31 JST（残り89分）で `DEADLINE`、01:30 JST で `DEADLINE`、06:30 JST（夏）で通る |
| T12 | **丸めの向き** | 損失は切り上げ、利益は切り捨て、建値は不利側。どの丸めでも許容損失を超えない |
