# シグナルの決め方

## いちばん大事な前置き

**点数は勝率ではない。** 場面がどれだけ整っているかを 0〜100 で表した数で、
それだけのもの。80点は「80%当たる」ではないし「80%上がる」でもない。
画面にもその旨を常に出してある。

過去の成績で検証していないので、この点数と実際の損益の関係は**まだ不明**。
検証は `backtester.py` / `performance.py` の担当で、Phase 1 では未実装。

## 3つの独立した判断

シグナルは3つの別々の判断を合わせて出す。混ぜない。

```
① 向き      decide_direction()  … LONG / SHORT / NEUTRAL
② 点数      score_setup()       … 0〜100
③ 強制条件  filters.check_all() … 見送りか否か
              ↓
        decide_signal()
```

### ① 向き — 点数を一切見ない

材料の多数決だけで決める。

| 材料 | 見るもの |
|---|---|
| H4 | EMA20 と EMA50 の上下 |
| H1 | EMA20 と EMA50 の上下 |
| M15 | HH/HL/LH/LL の構造 |
| 相場つき | TREND_UP / TREND_DOWN のとき |

- `require_h1_h4_agreement` が真のとき、**H1 と H4 が逆なら即 NEUTRAL**。
- そのうえで `min_agreement` 票以上かつ多数側であることを求める。
- 決まらなければ NEUTRAL。無理に方向を作らない。

### ② 点数 — 100点の配点

`config/signal_weights.json` で持つ。コードに数字を書かない。

| 項目 | 配点 | 材料 | 何を見るか |
|---|---|---|---|
| トレンド | 20 | あり | H4・H1 の EMA20/50/200 が向きと揃った割合 |
| 勢い | 15 | あり | M15 の MACD ヒストと RSI |
| 支持・抵抗 | 15 | あり | M15 終値から目標の帯までの ATR 倍 |
| 変動の大きさ | 10 | あり | H1 の ATR が普段の何倍か |
| 値動きの形 | 10 | あり | HH/HL/LH/LL・BOS・M5 のストキャス |
| 相関 | 10 | あり | ドル指数・米10年債・金・VIX・S&P500。**銘柄ごとに測る** |
| ニュース・指標 | 10 | あり | 次の重要指標までの余裕。**停止は強制条件で別建て** |
| 時間帯 | 5 | あり | ロンドン・NY・東京のどれが開いているか |
| スプレッド | 5 | あり | 上限に対する余裕 |

### 指標は「停止」と「余裕」を分ける

**発表前後の停止は強制条件で表す。点数では表さない。**
点数にすると、他の項目が高ければ上書きできてしまう。「指標の15分前」は、
どんなに場面が整っていても建てない条件。

| 出るもの | 何を表すか |
|---|---|
| 強制条件 | 指標の前後（blackout）に入っていれば NO_TRADE |
| 配点10点 | 次の重要指標までどれだけ余裕があるか |

| 状態 | 意味 |
|---|---|
| `QUIET` | 当面は関係する重要指標が無い |
| `UPCOMING` | 近いが blackout の外 |
| `ACTIVE` | blackout の中。**建てない** |
| `UNKNOWN` | 予定表が古い・読めない。**建てない** |

blackout は High が前30分・後15分、Medium が前後10分。Low は止めない
（数が多く、止めるとほぼ常時停止になる）。

**通貨が読めない指標を「関係なし」として捨てない。** 捨てると止めるべき
場面を見落とすので、全銘柄に関係ありとして扱う。

**古い予定表で「指標なし」と言わない。** これがいちばん危ない。取り込みが
36時間より古ければ `UNKNOWN` にして建てない。一方、予定表がそもそも
無い場合は「確かめようがない」ので配点から外すだけで、止めはしない
（取り込む前に何も出せなくなるのを避けるため）。

出所は Forex Factory の公開 JSON。`robots.txt` が `Disallow:` 空＝全面許可
であることを確認済み。

### 相関は決め打ちしない

「USDJPY はドル指数と相関する」と表に書いてしまうと、実際に相関が切れて
いる期間でもその前提で加点し続ける。**相関は変わるもの**なので、期間ごとに
測ってから使う。

1. 通貨ペアと材料の**収益率**を、時刻が揃う範囲で並べる
2. 相関係数を測る
3. `min_abs_correlation`（既定0.3）に満たない材料は**使わない**
4. 残った材料の直近の動きから「この銘柄はどちらへ行きやすいか」を出す
5. 一致度を |相関| で重み付けして平均する

実データ（2026-09時点、H1・240本）で測った例。

| 銘柄 | 使える材料 |
|---|---|
| EURUSD | ドル指数 −0.91 / 米10年債 −0.47 / 金 +0.56 |
| AUDUSD | ドル指数 −0.71 / 米10年債 −0.71 / 金 +0.61 / VIX −0.44 / S&P500 +0.42 |
| USDJPY | ドル指数 +0.73 / 米10年債 +0.52 |
| EURGBP・AUDNZD・ZARJPY・EURCAD・AUDCHF | **無し（0点）** |

材料は毎時 :20（米10年債）や :30（S&P500）に刻まれていて為替の :00 と
一致しない。時間足の枠に落としてから突き合わせる。**枠内のずれは残るので
相関は弱めに出る**が、弱く出るのは安全側（使えないと判定されるだけ）。

### 「測れない」と「測ったが弱い」を分ける

| state | 意味 | 配点の扱い |
|---|---|---|
| `KNOWN` | 使える材料があった | 一致度 × 10点 |
| `WEAK` | 材料は揃っているが相関が弱い | **0点。満点にも数える**（確認できないことは減点） |
| `UNAVAILABLE` | 突き合わせる材料が無い | 0点。**満点から外す** |

外さないと、材料を持たない環境で全体が沈んで何も出なくなる。
逆に `WEAK` を外すと、「確かめたが支えが無い」場面が有利になってしまう。

**合成データは実勢の材料と突き合わせない。** 時刻がたまたま合うだけで、
出てくる数字は相関を表していない（`is_synthetic` で判定）。

### 満点と、測れなかったときの扱い

相関とニュースの材料を繋いだので、**満点は100点**になった。
ただし銘柄によっては相関を測れず、予定表を取り込んでいなければ指標も
測れない。**測れなかった項目はその回だけ満点から外す**ので、分母は
分析ごとに変わりうる。

**区分の境目は「測れる配点に対する割合」で持つ。**

| 区分 | 割合 | いまの絶対点 |
|---|---|---|
| NO_TRADE | 0〜60% | 0〜60.0 |
| WATCH | 60〜70% | 60.0〜70.0 |
| SETUP | 70〜80% | 70.0〜80.0 |
| STRONG_SETUP | 80〜90% | 80.0〜90.0 |
| VERY_STRONG_SETUP | 90〜100% | 90.0〜100.0 |

絶対点で境目を持つと、**到達しうる最大と一致して満点以外は
BUY/SELL が出なくなる**。割合で持てば、ニュースを繋いで満点が
100点に増えたときも区分の意味が変わらない。

### 「相場の構造」を独立配点から畳んだ

従来は `market_structure` を15点の独立項目にしていた。配点の見直しで
`price_action`（10点）に畳んである。HH/HL/LH/LL と BOS/CHOCH は
値動きの形そのものなので、分類としては自然。

**ただし材料は捨てていない。** 実データの検証では、構造は数少ない
「順方向に効いた」項目だった（低得点 −0.234 → 高得点 −0.040）。
落とせば、測れた数少ない手がかりを失う。試験でも、構造が向きと一致した
銘柄で `price_action` に点が入ることを確かめている。

いくつか意図を書いておく。

- **勢い**: 順方向でも RSI が行き過ぎ（買いで70超、売りで30未満）なら
  満点にしない。飛びつきを高く評価しないため。
- **支持・抵抗**: 近いほど高い（押し目・戻りを評価する）。ただし
  ATR の 0.2 倍未満は抜ける危険があるので 0.6 倍に落とす。
- **変動の大きさ**: 大きいほど良いのではなく、**普段どおり（比 1.0 前後）が
  いちばん高い**。荒れている場面を高く評価しない。
- **相関 / ニュース**: **材料は繋いである**（`data/drivers` と
  `data/calendar`）。ただし取り込んでいなければ **0点**で、その回は
  満点からも外す。以前は相関5点の半分を「中立」として与えていたが、
  **持っていない材料に点が入るのは架空の加点**で、点数の意味を壊す。やめた。
  `config/signal_weights.json` の `data_available` で材料の有無を明示して
  あり、`false` の項目は満点に数えない。
  **取り込みは手動で、予定表は36時間で古くなる。** 古い予定表で
  「指標なし」と判断するのがいちばん危ないので、古ければ建てない。


### 点数の区分

| 点 | 区分 |
|---|---|
| 0〜59 | NO_TRADE |
| 60〜69 | WATCH |
| 70〜79 | SETUP |
| 80〜89 | STRONG_SETUP |
| 90〜100 | VERY_STRONG_SETUP |

### ③ 強制条件 — 点数では上書きできない

`filters.py`。1つでも当たれば **NO_TRADE**。

| 条件 | 内容 |
|---|---|
| 足の本数 | 各時間足に最低本数（既定60本）が要る |
| 鮮度 | 最後の足が `max_bars_behind`（既定3本）分より古い |
| スプレッド（絶対） | ペア別の上限 pips を超えた |
| スプレッド（相対） | M5 の ATR に対する比が上限（既定25%）を超えた |
| 損切り幅 | M15 の ATR が計算できない・小さすぎる |
| 変動が異常 | H1 の ATR が普段の 2.5 倍超 |
| 値動きが無い | H1 の ATR が普段の 0.35 倍未満 |
| 上位足の衝突 | H1 と H4 の向きが逆 |
| 上位足が不明 | H4 の向きが判定できない（**分からないことを「競合なし」にしない**） |
| 足の素性 | 頼んだ時間足と違う間隔の足が来ている |
| 未確定の足 | 最後の足がまだ完成していない |
| 未来の足 | まだ来ていない時刻の足が混ざっている |
| 期限切れ | `valid_until` を過ぎている |

「普段の何倍か」は**中央値に対する比**で見ている。以前は分位を使っていたが、
分位は定義上どんな系列でも一様に散るので「異常」の検出に使えない。
ほぼ一定の系列で 0 か 1 に張り付き、全銘柄が見送りになった。

## 相場つきと戦略の対応（点数とは別）

**戦略が違えば向きの決め方も違う。** トレンド追随は押し目を買うが、
持ち合いでは同じ場面が「上限に近い＝売り」になる。前提が違う相場つきに
同じ条件をそのまま当てはめると、根拠が無いのに売買シグナルが出る。

実際、外部レビューの指摘で確認したところ **LOW_VOLATILITY と TRANSITION で
BUY/SELL が出ていた**。持ち合いなのにトレンド追随の条件が自動的に成立して
いた形だった。

戦略は `backend/app/strategies.py` の `REGISTRY` に集めてある。

| 名前 | 何をするか | 点数の測り方 |
|---|---|---|
| `trend` | 上位足の向きと構造が揃った側に付く | trend |
| `breakout` | 帯を抜けた直後に付く。伸びきってからは追わない | trend |
| `momentum_flag` | 強く動いたあとの浅い押しで、同じ方向に付く | trend |
| `range` | 帯の端でだけ入る逆張り。真ん中では入らない | range |
| `failed_breakout` | 抜けたのに帯へ戻された側に付く | range |

相場つきごとに、試す戦略を**順番付きで**割り当てる。

| 相場つき | 試す順 |
|---|---|
| TREND_UP / TREND_DOWN | `trend` → `momentum_flag` |
| BREAKOUT | `breakout` → `trend` |
| RANGE / LOW_VOLATILITY | `failed_breakout` → `range` |
| TRANSITION / HIGH_VOLATILITY / NEWS / NO_TRADE | **無し**（理由つきで WAIT）|

**順に試して、最初に向きが出たものを採る。** 条件の厳しいほうを先に置く。
BREAKOUT で `breakout` を先に置くのは、抜けた直後は押し目ではないから。
RANGE で `failed_breakout` を先に置くのは、戻された事実があるぶん根拠が
一段強いから。

判定は `config/filters.json` の `regime_strategy.strategies` で持ち、
**点数では表現しない**。点数にすると高得点で上書きできてしまう。
一覧に無い相場つきは「戦略なし」として扱う。既定をトレンドにすると、
相場つきを増やしたときに黙って誤った戦略で判断してしまう。
設定に知らない名前があっても落とさず、その戦略だけ飛ばす（見送り側に
倒れる）。綴り間違いは `tests/test_strategies.py` で捕まえる。

### 戦略を増やすときの決まり

**増やせば強くなる、ということは無い。** 順に試すぶん「どれかが偶然
当てはまる」回数が増える。1件あたりの期待値が負なら、件数が増えるだけ
負けが増える。だから2つを必ず守る。

1. **どの戦略で入ったかを残す**（`AnalysisResult.strategy`、`Trade.strategy`）。
   混ぜて集計すると、効いていない戦略が効いている戦略の成績に隠れる。
2. **実データで1つずつ測る**（`scripts/measure_strategies.py`）。
   測る前の戦略は「候補」であって、戦略ではない。

合流の順序は `強制の見送り → 相場つきへの対応 → 点数の区分 → 方向`。
**点数95でも、対応する戦略が無ければ売買にはならない**（試験あり）。

### 持ち合いの逆張り（変動の小さい相場）

`decide_direction_range()`。**帯の端でだけ入る。真ん中では入らない。**
真ん中は、どちらへ動いても損切りが近く、取れる値幅も無い。

入る条件は4つで、ひとつでも欠ければ様子見にする
（設定は `config/filters.json` の `regime_strategy.range`）。

| 条件 | 既定 | なぜ |
|---|---|---|
| 帯の幅 | ATR の 1.5 倍以上 | 幅が無ければ当たっても取れない |
| 端までの距離 | ATR の 0.5 倍以内 | 端で入るから損切りを帯の外に置ける |
| 直近の抜け | 10本以内に終値で抜けていない | 抜けていれば持ち合いは終わっている |
| RSI | 買いは45未満／売りは55超 | 端に来ただけでは入らない |

**点数の項目と配点は戦略で変えない。** 変えるのは測り方だけ
（`config/signal_weights.json` の `range`）。

| 項目 | 追随での意味 | 逆張りでの意味 |
|---|---|---|
| トレンド 20点 | 上位足の向きと一致しているか | **向きが出ていないこと**（EMA が絡んでいるか） |
| 勢い 15点 | MACD・RSI が向きを支持 | RSI が入る側の端にあり、逆向きの勢いが弱まっている |
| 支持抵抗 15点 | 押し目・戻りの近さ（近すぎは減点） | 端への近さがそのまま根拠（近すぎの減点はしない） |
| 値動きの形 10点 | 構造の一致と BOS は**加点** | 構造は中立が良く、BOS は**減点**（持ち合いが崩れた合図） |

配点から外さないのは意図がある。外すと満点（attainable）が下がり、
少ない材料で売買の水準に届いてしまう。**「測れない」と「この戦略には
当てはまらない」は別のこと。**

実データでの検証結果は `docs/backtesting.md` に置く。
**効かなければ捨てる。** 持ち合い戦略があれば勝てる、という根拠は
それ自体には無い。

## 合流

```python
if filter_result.blocked:        return NO_TRADE   # ← 何よりも先
if quality is NO_TRADE:          return NO_TRADE
if direction is NEUTRAL:         return WAIT
if quality in (WATCH, SETUP):    return WAIT
return BUY if LONG else SELL
```

**95点でもスプレッドが上限超えなら NO_TRADE。** この順序は入れ替えない。

## 相場つき（regime）

判定の順序に意味がある。

```
足が無い → NO_TRADE
ADX が閾値超で EMA が揃っている → TREND_UP / TREND_DOWN
ボリンジャー幅が拡大 → BREAKOUT
ATR が極端 → HIGH_VOLATILITY / LOW_VOLATILITY
ADX が低い → RANGE
それ以外 → TRANSITION
```

変動の判定をトレンドより先に置いていたとき、**強い下降トレンドが
LOW_VOLATILITY に分類された**。トレンドを先に見るよう直してある。

## 指標の状態（news_state）

経済指標カレンダーを持っていないので、常に `UNKNOWN` を返す。
**推測では埋めない。** 画面にも「不明のまま」と出している。
指標発表前後を避ける機能は、カレンダーを繋ぐまで作らない。
